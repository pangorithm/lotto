# 전 회차 리플레이: 사건별 관측 적중률

2026-11-23 KST 스냅샷에 있는 2,054회 전부를 대상으로 삼았다. 각 상품의 최초 26회는 모델의 최소 학습량이 모이기 전이어서 예측이 없다. 78회를 오답으로 세지 않고 **1,976회, 9,880개 조합**을 채점했다. 구간은 이전 분석의 [날짜 기준 경계](period-analysis.md)를 그대로 사용했다. 사건은 결과를 나누는 기준일 뿐이며 경계에서 학습 이력을 초기화하지 않았다.

- **회차 적중률** = 다섯 조합 중 하나 이상이 어떤 등위든 맞은 회차 / 예측이 있던 회차. **조합 적중률** = 당첨 조건을 맞춘 조합 / 제출한 조합. 1등 확률, 수익률 또는 다음 회차의 보장 확률과는 다르다.
- 로또·720+는 실제 Rust 모델·수집기·임시 운영 DB·로컬 Slack을 거치는 리플레이로 진행했다. 각 상품 1회를 시작 자료로 넣고 2회부터 한 회차씩 공개했다. 이전까지 저장된 다섯 예측이 공개 뒤에도 불변인지, 당첨번호·보너스가 원천과 같은지 확인했다.
- **520은 종료된 상품**이라 운영 데몬의 실적이 아니다. 별도 오프라인 연구 모델이 직전 최대 104회의 1등 두 번호를 관측해 7개 조와 유효한 자리별 숫자의 빈도를 학습한다. 후보 5개를 만든 뒤 그 회차의 1–7등 발표 패턴으로 채점한다. 66회의 5등 기준 변경도 실제 발표된 자리 수를 따른다.
- 한 조합에 여러 조건이 겹치면 당첨 여부는 한 번만 세고 가장 높은 지급 등위로 분류했다. [집계 JSON](replay-period-rates.json)에 기간별 날짜·이력·등위별 조합 수와 회차 기준 Wilson 95% 참고 구간을 수록했다. 신뢰구간은 회차 단위 이항 근사이며, 기간에 따라 참확률이 고정됐음을 보증하지 않는다.

**얼마나 높은 등위였나?** 로또 140개 중 4등 5개·5등 135개, 720+ 153개 중 5등 2개·6등 14개·7등 137개, 520 450개 중 5등 1개·6등 23개·7등 426개였다. 어떤 상품에서도 1등은 관측되지 않았다. 520과 720+는 끝자리 일치 규칙과 당첨번호 개수가 다르므로 비율 자체를 모델 우열로 해석하면 안 된다.

**해석:** 앞선 8회의 로또 조합 적중률 15%는 같은 구간의 결과로 재현되지만, 전 기간에는 2.29%다. 공정한 로또에서 단일 조합이 본번호 3개 이상을 맞힐 이론 확률은 `Σ(k=3..6) C(6,k) C(39,6−k) / C(45,6)`로 약 2.38%다. 5개 조합이 번호를 공유하므로 회차 적중률을 `1−(1−p)^5`로 비교하지 않았다. 기간별 차이는 실측 빈도의 차이이며, 사건의 인과효과나 조작, 장비 결함을 증명하지 않는다. 이 자료는 과거에 이미 분석된 스냅샷이므로 독립적인 미래 검증 결과도 아니다.

## 재현

```sh
mkdir -p .tmp/qa
cargo test --release --locked --bin lottery-daemon all_active_rounds -- --ignored --nocapture > .tmp/qa/active-period-replay.log
python3 scripts/replay_pension520.py > .tmp/qa/legacy-period-replay.log
python3 scripts/summarize_replay.py .tmp/qa/active-period-replay.log .tmp/qa/legacy-period-replay.log > .tmp/qa/replay-period-rates.json
```

컨테이너에서는 `compose.test.yaml`의 `test` 이미지를 빌드하고 위 Cargo 명령을 `podman compose -p lotto-replay-full -f compose.test.yaml run --rm test` 뒤에 붙여 실행할 수 있다. 운영 볼륨과 실제 슬랙 웹훅은 사용하지 않는다.
