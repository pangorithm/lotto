# 최근 편향 가설을 사용한 회차 예측

`recent-bias-v1`은 **특정 번호·조·자리가 최근에 더 자주 나오는 편향이 다음 추첨에도 일부 지속된다**는 가설을 검정하는 실험 모델이다. 장비 결함 또는 조작 여부를 판정하는 모델은 아니다.

각 대상 회차 직전 최대 104회(최소 26회)만 읽는다. 번호 또는 자리의 추정 분포는 균등 기준 90%와 직전 관측 빈도 10%를 섞는다. 로또는 출현 점수 상위 6개를, 720+는 1등 조와 여섯 자리 각각에서 최빈 값을 고른다. 동점은 작은 값부터 고른다. 수축의 강도는 확률 점수에는 영향을 주지만, 균등 기준이 같은 항목의 순위를 바꾸지는 않는다. 로또의 보너스와 720+의 하위·보너스 결과는 학습에 섞지 않았다. 기록에 없는 기계 일련번호나 공 세트, 당시 알 수 없었던 과거 장비 구간은 입력하지 않는다. 모델은 일시적인 재현 가능한 번호 편향에 반응할 수 있으나, 어느 장비가 편향을 일으켰는지는 식별할 수 없다.

## 시간순 검증

2026-11-23 스냅샷의 마지막 로또 208회와 720+ 104회에서, 목표 회차를 항상 제외하고 바로 전 데이터로만 모델을 다시 적합했다. 표의 확률 손실은 작을수록 좋다. 두 상품의 손실 척도는 서로 비교할 수 없다.

| 상품·평가 회차 | 확률 손실 척도 | 실험 모델 | 균등 기준 | 후보 평균 일치 | 균등 기대 | 공정 추첨 가정에서 이만큼 이상 일치할 확률 |
|---|---|---:|---:|---:|---:|---:|
| 로또 1,044–1,251회 (208회) | 번호별 주변 Brier 손실 | 0.115567 | 0.115556 | 0.8125 | 0.8000 | 0.4232 |
| 연금복권720+ 239–342회 (104회) | 조·자리별 평균 로그 손실 | 2.203760 | 2.203564 | 0.7981 | 0.8000 | 0.5269 |

로또의 일치는 본번호 교집합 크기이고, 720+의 일치는 **조 하나와 여섯 자리의 위치별 일치**를 합한 값이다. 당첨 등위나 당첨 확률이 아니다. 표의 마지막 열은 독립 균등 추첨을 가정한 일치 수 우측 꼬리 확률이다. 로또는 초기하 분포, 720+는 조(1/5)와 자리(1/10)의 독립 벤치마크를 회차 수만큼 합쳤다.

**두 상품 모두 확률 점수에서 균등 기준을 이기지 못했다.** 로또 후보의 평균 일치 수는 기대보다 조금 높지만, 공정 추첨에서도 흔히 나올 수 있는 정도다. 반대로 이 결과가 편향 부재나 조작 불가능을 증명하는 것도 아니다. 하나의 최근 빈도 모델만 평가했으며, 이 과거 자료를 이미 다른 분석에 사용했으므로 완전한 미공개 검증 세트가 아니다. 운영에서는 점수순 5개를 회차 전에 저장하고 실제 당첨번호와 각각 대조한다. 균등 기준은 무작위 번호를 별도로 만들지 않고 수학적으로 계산한다. 위 일치 수와 꼬리 확률은 **1순위 조합 하나**의 평가이며, 5개 중 최고 성과가 아니다.

## 스냅샷에서 계산된 1순위 실험 후보

- 로또 1,252회: **13, 16, 18, 27, 28, 38**
- 연금복권720+ 343회: **3조 034223**

```sh
cargo run --locked -- --db lottery.sqlite3 backtest
```

명령은 원본 DB를 읽기 전용으로 열고 운영과 같은 모델 코드를 사용한다. JSON의 `snapshot_next_candidates`에 5개가 모두 나온다. 로또는 6개의 주변 출현 점수 합을 최대화하며, 720+는 조·자리의 주변 점수 곱을 사용한다(독립 순위 모형). 가까운 순위의 조합끼리는 번호가 많이 겹칠 수 있고, 다양성을 목적으로 일부러 점수를 낮추지 않는다.

## 발표 순서 리플레이

아래 8주는 빠른 회귀 검사다. 모든 상품·사건 구간의 적중 건수와 분모는 [전 회차 리플레이](full-replay-rates.md)에 별도로 정리했다.

[리플레이 테스트](../src/replay.rs)는 원본의 상품별 과거 104회만 복사한 임시 시드에서 시작한다(로또 1,243회·720+ 334회까지). 로컬 HTTP 서버가 로또 1,244–1,251회와 720+ 335–342회 결과를 추첨일 순으로 **한 회차씩** 공개한다. 공개 시각은 실제 서버 응답 로그가 아니라 추첨 당일 22:00 KST로 설정한 가상 시각이다. 운영 코드가 공개 전에 저장한 5개가 그대로 남는지, 결과·보너스가 원본과 일치하는지, 다음 예측과 비교 알림이 재시작·반복 조회에도 중복되지 않는지 검사한다.

각 상품 8회×5조합을 대조했다. 로또는 본번호 3개 이상이 일치한 조합이 6개였고, 두 상품 모두 1등 일치는 없었다. 720+ 보너스 완전 일치도 없었다. 이는 **저장·수집·채점 순서**를 재현한 결과다. 5개 예측의 숫자는 서로 겹칠 수 있으며 이미 알려진 8주 기록만으로 모델의 예측 우위나 추첨기 편향을 입증할 수 없다.

```sh
cargo test --locked --bin lottery-daemon replay:: -- --nocapture
podman compose -p lotto-replay-test -f compose.test.yaml build test
podman compose -p lotto-replay-test -f compose.test.yaml run --rm test cargo test --release --locked -- --nocapture
```

테스트는 재현용 로컬 응답과 임시 SQLite만 사용하며 실제 슬랙과 운영 볼륨은 사용하지 않는다.
